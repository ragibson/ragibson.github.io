My background with the TI-84 #

Growing up, the TI-84 was the standard scientific calculator that we were allowed to use in math courses.

It is a relatively simple machine with basic statistical and graphing capabilities that comes with an easy-to-learn programming language known as “TI-BASIC”.

An example program that computes the quadratic formula looks like this:

Prompt A,B,C
(-B+√(B²-4AC))/(2A)→X
(-B-√(B²-4AC))/(2A)→Y
Disp "ROOTS:",X,Y

Notably, mathematical operations are all built-ins here, which helps keep the language about as basic as it gets for the user.

This was really the first programming language I ever worked with, and then I dabbled with the corresponding assembly language afterward. In my case, I didn’t have a manual on hand, so I learned most of the syntax through trial and error while bored in my early math classes. Luckily, there is a catalogue of all keywords available on the calculator itself.

There’s a whole universe of interesting topics I could discuss here1, but I fundamentally believe this calculator and its lower-level introduction to programming had a significant influence on my personal interests, academic choices, and career trajectory.

A quick introduction to PICO-8 #

PICO-8 is a so-called “fantasy console” that tries to recreate the usage and development experience of early computers.

By modern standards, the display is very low resolution, the programming language is simplistic, the performance and storage are limited, and most games use pixel art and 8-bit music.

However, much like the TI-84’s 96x64 monochrome screen and low memory limits, these constraints give the games a unique feel and help keep the scope of projects small enough to actually complete them.

It is also enormously portable due to the low system requirements, and is often exported to web applications for easy use in a browser. This is far easier than when I exchanged games through the TI link cable!

Importantly, the entire development process is bundled into the console itself, and you can easily view and edit all the code and assets of any game you play.

PICO-8 uses a variant of a programming language called Lua. It is higher level than BASIC but still requires you to stay under memory limits and reason about control flow and global state much like you would in a lower-level environment. No standard libraries are included.

This keeps program logic simple enough that you can hold most of it in your head at one time. Otherwise, you would create abstraction layers yourself in order to better reason about the code (likely kept in separate “tabs” of the coding environment).

Similarly, all the artwork is created inside the fantasy console itself.

In the sprite and map editors, you can use your mouse to paint a full sprite sheet for your game and (optionally) a map for the player to move around in.

Above are the graphics for a traditional side-scroller game, but there is no restriction on the type of game you create, so long as it fits within the storage and performance requirements of the console.

Finally, all the sound effects and music are created in the last two tabs of the editor.

All of these views are very intuitive to use and play around with! Once you know the basic syntax, you can get going simply by experimenting with the interface and only need the manual or guides for more complicated features.

Potential use in education and concerns about AI #

I have always thought that it would be best to learn programming by starting with a simple programming language and then building layers of complexity on top of that.2 This is exactly how I got started through TI-BASIC.

Much like the TI calculators, PICO-8 invites the same sort of exploration that promotes learning and building things on your own. That practice is absolutely vital as you move into larger systems and more complex logic.

In my experience, when students start with extremely high-level languages like Python, it is easy to ignore how their programs are actually working under the hood. Without a good sense of the lower layers, I often see newer developers accept that their code “just runs this slow”, “needs” more RAM than they have available, or celebrate a 50% speedup from parallelism (which would actually generally indicate quite poor parallelism).

These issues have worsened with the rise of AI. Many junior employees now seem to have large knowledge gaps due to overreliance on AI, and we are already starting to see worse learning outcomes due to AI in general.

You truly need to have prior experience walking the path to a solution yourself since that is precisely when you are doing the most learning, but it is all too tempting to use AI as a shortcut. If you constantly reach for ChatGPT or Claude, you lose (or perhaps never gain) both the ability to reason about the trade-offs of various design choices and the boundaries of what is possible with the tools you have on hand.3

On a positive note, this has created an environment where I think PICO-8 really shines.

  • There are no modern distractions (or AI assistants) that pull your focus away from the problem solving and design of the program itself. You have to perform all the reasoning with your own brain.
  • As you build up larger programs, the need for abstraction and helper functions naturally becomes apparent in order to easily reason about your own logic. Maintaining a simple, clean code structure becomes very important and obviously useful.
  • The goal of creating games promotes exploration and iteration, while hopefully having fun doing it!

In fact, PICO-8 maintains an Education Edition that is freely available for experimentation, and I have heard of college courses and high schools using it in their curriculums.

I believe this would be great to extend to younger students so that they can get a feel for the essential aspects of programming before they are introduced to higher-level languages and generative AI.

Even for students who have mostly worked at a higher level, spending time in a simpler environment like this is a great way to exercise the fundamentals of programming. Project design, reasoning, code reviews, and problem solving still require these skills, even as the industry expands the use of AI coding agents.

I would like to picture a student today curiously poking through the various sections of PICO-8’s editors in much the same way that I did on my TI-84 calculator as a child. That is the type of experience I would want every new programmer to have first, especially now that so many people default to working with code only through AI assistants.

See also and references #

Ironically, PICO-8 was heavily inspired by older home computers (not TI calculators), so you could replace much of my discussion above with a Commodore 64, Apple II, or BBC Micro, though these were all before my time.

To learn more about PICO-8, please see the following links.

  • The main PICO-8 website where the fantasy console is available for purchase or free to use in the Education Edition. A huge number of game carts are free to explore on the same website.
  • The learning resources on the PICO-8 website. “Game Development with PICO-8 by Dylan Bennet” and the first “PICO-8 Fanzine” are excellent resources for a beginner, and the manual is short enough to read through in its entirety.
  • The Celeste cart in particular, which is the game I used for the example PICO-8 screenshots. This is the original version of the famous 2018 video game of the same name, created over the course of three days.
  • Shmupgrade, a simple arcade-style space shooter that I made in PICO-8 for fun.
  • “Make Tiny Games.”, a YouTube video by Juniper Dev that discusses their experience in a university course devoted to making games in 8-bit game engines like PICO-8.
